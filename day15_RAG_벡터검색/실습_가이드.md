## 교안으로 개념 잡기

### 교안_01 — RAG 아키텍처와 벡터 검색의 필요성
- **1. 왜 RAG 인가** — LLM 의 환각·최신/비공개 지식 부재, 그리고 검색으로 보강하는 아이디어.
- **2. RAG 의 큰 그림** — 질문(Query) → 검색기(Retriever) → 생성기(Generator), 인덱싱 타임 vs 쿼리 타임.
- **3. RAG 를 이루는 구성요소** — 문서·임베딩 모델·벡터 저장소·유사도 검색·컨텍스트·LLM.
- **4. 직접 만드는 검색기** — 12일차 코사인 유사도로 Top-K 검색기를 만들고, 선형 스캔의 한계를 본다.
- **5. 솔루션 비교** — ChromaDB(로컬)·Qdrant(오픈소스 프로덕션)·Pinecone(관리형 클라우드).

### 교안_02 — 벡터 검색과 벡터 DB 구축
- **1. 의미 기반 검색 vs 키워드 검색** — 단어가 겹치지 않아도 뜻으로 찾는다.
- **2. ChromaDB** — 클라이언트·컬렉션 만들기, 우리 임베딩을 `embeddings=` 로 직접 적재(add).
- **3. Top-K 검색** — `query(query_embeddings=…, n_results=…)` 와 반환 딕셔너리 읽기.
- **4. 메타데이터 필터** — `where={'type': '역사'}` 로 조건을 함께 건다.
- **5. ANN·HNSW** — 전부 비교하지 않고 빠르게 찾는 근사 최근접 탐색의 개념(계층 그래프·정확도↔속도 맞바꿈)과
  손잡이(`search_ef`·`M`)의 역할. 이어서 **거리 기준(`hnsw:space`) `cosine`·`l2`·`ip` 를 바꿔 가며** 같은
  질문을 검색해, 정규화한 벡터에서는 **세 기준의 순위가 똑같고** 정규화를 끄면 **`l2` 는 순위가 뒤바뀌고
  `ip` 는 다른 문서까지 끌어올리는** 것을 확인한다 — 왜 '정규화한 벡터 + `cosine`' 이 실무 기본값인지 눈으로 본다.
- **6. Qdrant 로 재현** — `:memory:` 로 같은 코퍼스를 색인·검색해 도구를 비교한다. 두 DB 의 **저장 위치**
  (메모리 vs 폴더)와 실제로 생기는 파일도 함께 본다.

### 교안_03 — 검색 결과로 답 생성하기 (RAG 완성)
- 앞에서 만든 검색기가 찾아온 문서를 **근거로 LLM 에게 건네** 답을 쓰게 한다. 여기서 **질문 → 검색 → 생성**
  한 바퀴가 닫히고 RAG 가 완성된다. **`.env` 의 `OPENAI_API_KEY` 가 필요하다**(실제 호출).

> 교안의 **함께 따라하기**는 배포본에 지시 주석만 있습니다. 직접 타이핑해 보고, 완성 코드는 `정답/` 노트북에서
> 확인하세요.

## 과제로 손에 익히기

### 과제_LV1 (기초) — 도서 소개 의미 검색 · `data/books.csv`
- 1. 데이터 살펴보기(서술) — 2. 문장 하나 임베딩 — 3. 여러 문장 임베딩
- 4. 코사인 Top-1(질문→가장 비슷한 책) — 5. 코사인 Top-3(특정 책과 비슷한 책)
- 6. 컬렉션 만들고 add — 7. query Top-3 — 8. 다른 질문 query
- 9. **키워드 검색과 의미 검색은 무엇이 다를까** — 같은 질문을 `str.contains` 낱말 매칭과 의미 검색으로 각각 돌려 비교
- 10. 필터(추리 장르) — 11. 필터(동화 장르) — 12. 솔루션 비교(서술)

### 과제_LV2 (응용) — 상품 설명 검색 파이프라인 · `data/products.csv`
- 1. 색인 파이프라인(임베딩+생성+add) — 2. 의미 검색(등산 장비)
- 3. 분류 필터(전자기기) — 4. 숫자 필터(3만 원 미만)
- 5. 조합(의미 검색 + 분류 필터) — 6. 숫자 필터(10만 원 이상)
- 7. 여러 질문 일괄 검색(반복) — 8. Top-K 비교(K=1 vs K=5)
- 9. **같은 검색을 Qdrant 로 재현**(`:memory:` 클라이언트 → 컬렉션 → upsert → `query_points`)
      · 도구가 달라도 뼈대는 같다 — 자가채점이 **ChromaDB 1위와 Qdrant 1위가 같은지** 대조한다
- 10. **무엇과 무엇을 맞바꾸나**(서술형, 자가채점 없음) — `K` 의 맞바꿈(재현율↔정밀도·비용)과 `ANN` 의 맞바꿈(속도↔정확도)을 **구분해** 설명한다
- 11. **검색 결과를 근거로 답 생성** — 찾아온 상품 문서를 컨텍스트로 묶어 LLM 에게 건네고 추천 문장을 쓰게 한다
      · 🔑 `.env` 의 `OPENAI_API_KEY` 필요 — **실제 API 호출이라 요금이 조금 듭니다**(호출 1회)

### 과제_LV3 (통합) — 사내 FAQ 시맨틱 검색봇 · `data/faqs.csv`
- 문제 1. 색인 + 검색 함수(`search_faq`) 만들기 (자가채점)
- 문제 2. 숫자 메뉴 루프로 대화형 검색봇 완성 (`handle_choice` 자가채점 1개 + 메뉴 루프는 직접 실행 — 번호 선택, 0 종료)
      · 자가채점이 **여섯 질문의 결과가 실제 검색에서 나온 분류·답변인지**까지 대조한다(형식만 맞춘 답은 통과하지 못한다)
- 문제 3. **분류를 좁혀 찾는 고급 검색 + 정확도 점검** (자가채점 2개)
      · 1단계 `search_faq_in(question, category=None)` — `where` 필터를 조건부로 얹기
      · 2단계 평가셋 5문항으로 **필터 없이 4/5 vs 좁혀서 5/5** 비교
      · ⚠️ 그 5/5 는 검색이 똑똑해진 게 아니라 **정답 분류를 미리 알려 준 것** — 해설에서 이 함정을 짚는다
- 문제 4. **찾아온 FAQ 를 근거로 답변 생성** — 검색된 FAQ 를 컨텍스트로 LLM 에게 건네 상담 답변을 쓰게 한다
      · 🔑 `.env` 의 `OPENAI_API_KEY` 필요 — **실제 API 호출이라 요금이 조금 듭니다**

## 막혔을 때

- **모델 로딩이 느려요** — 처음 한 번만 내려받습니다. 이후엔 캐시에서 빠르게 불러옵니다.
- **`OpenAIError: Missing credentials` 가 떠요** — 생성 문제(교안_03 · LV2 11번 · LV3 4번)는 API 키가 필요합니다.
  `cp .env.example .env` 로 복사하고 `OPENAI_API_KEY` 를 채운 뒤 **커널을 다시 시작**하세요. 앞의 검색 문제들은
  키 없이도 그대로 돌아갑니다.
- **`create_collection` 에서 "already exists" 에러** — 같은 이름이 이미 있어서입니다. 실습에선
  `get_or_create_collection` 을 쓰면 여러 번 실행해도 안전합니다.
- **검색 결과를 꺼내는데 리스트가 두 겹이에요** — `query()` 는 질문을 여러 개 받을 수 있어 결과가 한 겹 더
  감싸여 나옵니다. 질문이 하나면 `res['ids'][0]` 처럼 `[0]` 으로 꺼내세요.
- **숫자 필터가 안 걸려요** — 메타데이터의 가격을 `int(...)` 로 넣었는지, `{'$lt': 30000}` 처럼 연산자로
  감쌌는지 확인하세요.
- **검색 결과가 예시와 조금 달라요** — 임베딩 검색은 하드웨어에 따라 미세하게 흔들릴 수 있습니다. 자가채점은
  '기대 문서가 상위에 포함되는지'로 느슨하게 보므로 통과하면 정상입니다.

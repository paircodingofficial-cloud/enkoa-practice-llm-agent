# 📗 앱 배포하기

앱을 완성했으면 **인터넷에 배포**해 누구나 쓰게 만듭니다.
이 강의는 대부분 브라우저와 터미널에서 직접 진행합니다.

> git 명령(`add`·`commit`·`push`)과 브랜치·Pull Request는 앞선 단원에서 이미 익혔습니다. 여기서는 **배포에 필요한 만큼만** 씁니다.

> 화면을 하나씩 따라가는 그림 자료는 강의 교안 **"Streamlit 앱 배포: GitHub에서 Community Cloud까지"** 에 있습니다. 이 문서는 그 요약 체크리스트입니다.

---

## 1. Streamlit Community Cloud 배포

Streamlit 앱은 **Streamlit Community Cloud**(무료)로 가장 쉽게 배포합니다. 저장소에 올린 앱을 그대로 가져가 실행하는 방식이라, 배포 준비물은 **저장소·의존성 목록·비밀 키 관리** 세 가지입니다.

### 배포 체크리스트

아래를 위에서부터 하나씩 확인하며 진행하세요.

- [ ] **1) 저장소에 앱을 올렸다**: 실행할 앱 파일(예: `main.py`)이 저장소에 있어야 합니다.
- [ ] **2) 의존성 파일이 저장소 루트 또는 앱과 같은 폴더에 있다**: 배포 서버는 그 파일만 보고 라이브러리를 설치합니다. `uv` 를 쓴다면 `pyproject.toml` 과 `uv.lock` 을 **짝으로** 올립니다.
- [ ] **3) 비밀 키가 코드에 들어 있지 않다** : `.streamlit/secrets.toml` 은 `.gitignore` 에 있어야 합니다(이 폴더의 `.gitignore` 에 이미 들어 있습니다).
- [ ] **4) https://share.streamlit.io 에 로그인**했다.
- [ ] **5) Create app → Deploy a public app from GitHub** 를 눌러 **저장소 / 브랜치 / 메인 파일 경로**를 선택했다.
- [ ] **6) Advanced settings → Secrets** 에 API 키를 넣었다(코드에 넣지 않습니다):
      ```toml
      OPENAI_API_KEY = "sk-..."
      ```
- [ ] **7) Deploy** 를 눌러 `https://<앱이름>.streamlit.app` 주소를 받았다.

**확인 기준**: 배포된 주소를 다른 기기(휴대폰 등)에서 열었을 때 앱 화면이 뜬다.

> 코드를 저장소에 `git push` 하면 배포된 앱이 **자동으로 갱신**됩니다. 별도 재배포 버튼을 누를 필요가 없습니다.

## 2. 의존성은 uv 로 관리한다

배포 서버는 의존성 파일을 `uv.lock` → `Pipfile` → `environment.yml` → `requirements.txt` → `pyproject.toml` 순으로 찾아 **처음 발견한 하나만** 씁니다. 우리는 로컬 환경을 `uv` 로 만들었고 `uv.lock` 이 1순위이므로, 그 잠금 파일을 그대로 올리면 서버가 **같은 버전으로** 환경을 만듭니다.

배포용 프로젝트는 앱에 필요한 것만 담아 새로 만드는 편이 깔끔합니다.

```bash
uv init my-streamlit-app -p 3.12
cd my-streamlit-app
uv add streamlit pandas plotly seaborn matplotlib \
       langchain langchain-openai langchain-chroma chromadb
uv run streamlit run main.py     # 올리기 전에 로컬에서 확인
```

저장소에 올릴 것은 `pyproject.toml`(무엇이 필요한지)과 `uv.lock`(어떤 버전으로 설치할지) **두 개**입니다. `.venv/` 는 올리지 않습니다.

**함정 세 가지**

1. **`uv.lock` 만 올리면 안 됩니다.** 잠금 파일에는 버전만 있고 무엇이 필요한지는 `pyproject.toml` 에 있습니다. `uv.lock` 만 있으면 `error: No pyproject.toml found in current directory or any parent directory` 로 멈춥니다.
2. **의존성 파일은 하나만 둡니다.** 여러 개면 먼저 만난 하나만 쓰고 나머지는 무시합니다. `requirements.txt` 를 고쳐도 저장소에 `uv.lock` 이 있으면 아무 일도 일어나지 않습니다.
3. **파이썬 버전을 맞춥니다.** `pyproject.toml` 의 `requires-python` 과 배포 폼의 **Python version** 이 어긋나면 설치가 시작도 못 합니다. Community Cloud 기본값은 3.12 이므로 `uv init -p 3.12` 로 만들었다면 그대로 맞습니다.

라이브러리를 추가할 때는 `uv add <이름>` 을 쓰세요. `pyproject.toml` 과 `uv.lock` 이 함께 갱신되고, 없는 이름이면 그 자리에서 실패해 배포 전에 오타를 잡아 줍니다(`uv add sklearn` 은 `scikit-learn` 을 쓰라고 알려 줍니다).

> 이 폴더의 `requirements.txt` 는 로컬 실습용 목록입니다. 그것만 올려도 배포는 됩니다(서버가 `requirements.txt` 도 uv 로 설치합니다). 단 uv 파일과 함께 두지는 마세요.

## 실습 과제 (직접 해보기)

1. 이 프로젝트를 본인 저장소에 올린다.
2. `uv init` 으로 배포용 프로젝트를 만들고, 앱이 실제로 `import` 하는 것만 `uv add` 한다. `pyproject.toml` 과 `uv.lock` 을 함께 올린다.
3. Streamlit Community Cloud 로 배포하고 주소를 공유한다.
4. Secrets 에 키를 넣어 챗봇·문서 Q&A 페이지가 배포 환경에서도 동작하는지 확인한다.
5. 앱 제목을 한 줄 바꿔 `git push` 한 뒤, 배포된 화면이 자동으로 갱신되는지 확인한다.
6. 대시보드의 한글 라벨이 두부(□)로 나오면 `packages.txt` 를 추가해 해결한다.

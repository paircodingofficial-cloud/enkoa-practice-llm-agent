# 데이터베이스 기초 실습 가이드 — 진행 체크리스트

관계형 DB 설계·SQL·ERD 를 **sqlite** 로 배우고, 벡터 검색과 RAG 는 **Supabase(PostgreSQL)+pgvector** 로 넘어가는 단원입니다.
아래 체크박스를 순서대로 지워 나가세요. 과제의 완료 기준은 **자가채점 셀에서 `✅ 통과!` 가 출력되는 것**입니다.

## 이 단원의 실습 환경 — 두 가지

| 자료 | 데이터베이스 | 준비물 |
|---|---|---|
| 교안_01 · 교안_02 · 과제 LV1 · 과제 LV2 | **sqlite** (파이썬 표준 라이브러리, 파일 하나) | 없음 — 바로 실행됩니다 |
| 교안_03 · 과제 LV3 | **Supabase + pgvector** (`supabase-py`) | Supabase 무료 프로젝트 · `.env` · (LV3 만) OpenAI 키 |

앞부분은 설치도 가입도 없이 시작하고, **벡터를 다뤄야 하는 뒷부분에서만** 클라우드로 옮겨 갑니다.
sqlite 와 PostgreSQL 의 문법 차이는 교안_03 §1 에 표로 정리돼 있습니다.

## 1. 교안_01 데이터베이스 설계와 ERD (강사와 함께)

> 교안은 **쇼핑몰 도메인**(고객·주문·상품·후기)으로 배웁니다. 과제(학사·서점·여행지)와 데이터가 달라,
> 개념을 새 데이터에 **적용**하는 훈련이 됩니다. 강사용 완성본은 `정답/교안_01_정답.ipynb`.

- [ ] sqlite 로 첫 표 만들기 — 파일 하나가 데이터베이스, `CREATE TABLE` · `INSERT` · `SELECT`
- [ ] **SQL 을 적는 약속** — 키워드는 대문자, 표·열·별칭은 소문자. 왜 그렇게 쓰는지
- [ ] 데이터 타입 — 규칙 없는 표에 이상한 값이 들어오는 것을 보고 `STRICT` 로 막기 (🖐️ 따라하기)
- [ ] 제약조건 — `NOT NULL` · `UNIQUE` · `CHECK` · `DEFAULT` 를 걸고 위반이 거부되는 것 확인 (🖐️ 따라하기)
- [ ] 키와 관계 — PK · FK · 1:1 · 1:N · M:N, 그리고 **`pragma foreign_keys` 함정** (🖐️ 따라하기)
      (응용에서는 표 수준 `FOREIGN KEY (열) REFERENCES 표(열)` 도 써 봅니다 — 열이 여러 개인 외래키는 이 형태로만 쓸 수 있습니다)
- [ ] ERD — 까마귀발 읽기, 설계 네 걸음, 실무 4패턴, 흔한 실수, 이름 짓는 관례 (🖐️ 따라하기: 장바구니 설계 서술)
- [ ] INSERT 더 깊이 — 일부 열 · 여러 행 · `RETURNING` · **파이썬으로 적재: 문장에 값을 이어 붙이면 따옴표에서 깨진다 → `executemany` 파라미터 바인딩(`?`)** (🖐️ 따라하기)
- [ ] `UPDATE` · `DELETE` — 기본형 · 여러 열 한 문장 · 새 값 자리의 계산식 · `RETURNING` (🖐️ 따라하기)
      (**`WHERE` 를 빠뜨리면 표 전체가 대상** — 같은 `WHERE` 로 `SELECT` 를 먼저. 부모 삭제를 막는 외래키와 `ON DELETE` 옵션까지)
- [ ] **트랜잭션 제어어** — `BEGIN` 으로 묶고 `COMMIT`(확정) 또는 `ROLLBACK`(되돌리기). `DELETE` 사고 되돌리기, 중간에 실패하면 앞의 성공까지 함께 되돌아가는 것까지 실행으로 확인
- [ ] 표 고치기 — `ALTER TABLE ADD COLUMN` (🖐️ 따라하기)
- [ ] 🚀 응용 클론코딩 — **장바구니를 중간표(M:N)로 구현**하고 복합 기본키·외래키가 막는 것까지 확인
- [ ] ✅ 바로 확인 퀴즈 전부 풀고 정답 보기로 확인

## 2. 교안_02 SQL 조회와 결합 (강사와 함께)

- [ ] `SELECT` · `WHERE` — 필요한 열·행만, 계산 열과 별칭(`AS`)
- [ ] `ORDER BY`(다중 기준·`DESC`) · `LIMIT` · `OFFSET`
- [ ] 조건 심화 — `AND`/`OR`/`NOT` 과 괄호, `BETWEEN` · `IN` · `LIKE` · `IS NULL` · `DISTINCT`
- [ ] 집계 — `count(*)` 와 `count(열)` 의 차이를 결과로 확인, `sum` · `avg` · `max` · `min`
- [ ] `GROUP BY` · `HAVING` — `WHERE` 와의 차이, **적는 순서와 실행 순서**(그림으로 확인), 집계를 `WHERE` 에 쓰면 나는 오류를 직접 보기
- [ ] `JOIN` — 번호 대신 이름이 붙은 한 줄 (🖐️ 따라하기)
- [ ] `LEFT JOIN` — 짝 없는 행까지, `coalesce` 로 0 채우기, 3표 잇기 (🖐️ 따라하기)
- [ ] **같은 조건을 `ON` 에 둘 때와 `WHERE` 에 둘 때 결과가 다르다** — 남는 고객 수를 나란히 확인
- [ ] 집계 결과를 표로 남기기 — `INSERT INTO ... SELECT` (과제 LV2 에서 그대로 씁니다)
- [ ] **인덱스** — 자주 거르는 열에 `CREATE INDEX`, 갱신이 느려지는 대가 (교안_03 의 벡터 인덱스로 이어집니다)
- [ ] 서브쿼리 — 스칼라(`> (SELECT avg(...))`) · 목록(`IN (SELECT ...)`) · **`NOT IN`** (🖐️ 따라하기)
- [ ] **상관 서브쿼리** — 바깥 행을 가리키면 행마다 다시 계산됩니다. `UPDATE ... SET 열 = (SELECT ... WHERE 안쪽 = 바깥)` 까지
- [ ] 🚀 응용 클론코딩 — 월간 매출 리포트 한 장

## 4. 과제 (자기 주도, 자가채점 `✅ 통과!` 기준)

> 같은 개념을 **다른 유형 2문제**로 익히도록 짝지어 두었습니다(예: `AND` ↔ `OR`, 앞 패턴 ↔ 끝 패턴).
> 짝 문제까지 풀어야 실력이 굳습니다.

### 과제_LV1_기초 — 26문 · 학사 데이터 · sqlite (권장 150분 내외)

표 만들기(1~4) → 조회(5~18) → 세고 묶기(19~23) → 바꾸고 지우기(24~25) → ERD 읽기 서술(26)

- [ ] 1 `CREATE TABLE` · 2 `INSERT` + `RETURNING` · 3 `INSERT` 일부 열 + 파라미터 바인딩(`?`) · 4 `ALTER TABLE`
- [ ] 5 `SELECT *` · 6 열만 고르기 · 7 `AND` · 8 `OR` · 9 `BETWEEN` · 10 `IN`
- [ ] 11 `LIKE` 앞 · 12 `LIKE` 끝 · 13 `IS NULL` ↔ `IS NOT NULL`(짝) · 14 `DISTINCT` · 15 `DISTINCT`(다른 표)
- [ ] 16 `ORDER BY` 다중 · 17 `LIMIT`+`OFFSET`(두 번째 페이지) · 18 계산 열과 `AS`
- [ ] 19 `count(*)`/`count(열)`/`count(distinct)` · 20 `sum`·`avg` · 21 `max`·`min`
- [ ] 22 `GROUP BY` · 23 `GROUP BY`(다른 표) · 24 `UPDATE` · 25 `DELETE` + 트랜잭션(`BEGIN`→`ROLLBACK`→`COMMIT`)
- [ ] 26 ERD 읽기 (서술 — 정답 노트북의 모범 서술과 비교)

> 데이터를 **바꾸는** 문제(1~4 · 24 · 25)는 모두 새로 만드는 `club` 표에서만 합니다.
> 그래서 조회 문제의 답은 앞 문제를 어떻게 풀었든 달라지지 않습니다.

### 과제_LV2_응용 — 16문 · 마당서점 · sqlite (권장 180분 내외)

- [ ] 1 `HAVING` · 2 `HAVING`(다른 표) · 3 `JOIN` · 4 3표 `JOIN`
- [ ] 5 `LEFT JOIN`+`IS NULL` · 6 `LEFT JOIN`+집계+`coalesce`
- [ ] 7 스칼라 서브쿼리 · 8 `IN` 서브쿼리 · 9 `JOIN`+`GROUP BY` · 10 기간 조건+집계
- [ ] 11 `LEFT JOIN`+`GROUP BY`+`HAVING`(주문이 적은 고객, 0건 포함)
- [ ] 12 3표 `JOIN`+기간+출판사 조건+집계
- [ ] 13 `CREATE` + `INSERT INTO ... SELECT` (우수고객 명단 만들기)
- [ ] 14 `UPDATE` + 상관 서브쿼리 (명단을 7월 기준으로 다시 계산)
- [ ] 15 `DELETE` + 서브쿼리 (7월에 안 산 고객은 명단에서 빼기)
- [ ] 16 `DROP TABLE` (집계용 임시 표 정리)

> 데이터를 **바꾸는** 문제는 마지막 넷(13~16)뿐이고, 그것도 13번에서 새로 만든 `vip_customer` 안에서만 바뀝니다.
> 그래서 1~12번의 답은 앞에서 무엇을 실행했든 달라지지 않습니다. 13~16 은 **만들고 → 갱신하고 → 추려 내고 → 정리하는** 한 흐름입니다.

### 과제_LV3_통합 — 2문 6단계 · 여행지 100곳 · Supabase + pgvector + OpenAI (권장 60~90분)

교안과 **다른 데이터**로 같은 절차를 처음부터 끝까지 혼자 세워 봅니다. 좁힐 수 있는 열이 **둘**(`region`·`spot_type`)이라 조건을 겹쳐 쓸 수 있습니다.

- [ ] **문제 1. 여행지를 담고, 뜻으로 찾기** — 1단계 임베딩해 표에 담기 → 2단계 뜻으로 찾고 조건으로 좁히기(지역·유형) → 3단계 `search_spot()` 으로 묶기
- [ ] **문제 2. 근거로 추천하고 출처를 붙이기 (RAG 완성)** — 1단계 근거를 한 덩어리 글로 → 2단계 `recommend()` (근거가 문턱을 못 넘으면 **LLM 을 부르지 않고 물러섭니다**) → 3단계 세 질문으로 시험

> 문제 1 은 Supabase 만 있으면 풀립니다. **OpenAI 키는 문제 2 부터** 필요합니다.
> **임베딩 대상은 "이름 + 설명"** 입니다 — 적재와 검색이 서로 다른 것을 임베딩하면 에러 없이 순위만 틀어집니다.
> CSV 의 `type` 열은 표에서 **`spot_type`** 이라는 이름으로 들어갑니다(`type` 을 피한 이유는 지문에 있습니다).

## 1. 교안_01 — 대화·파라미터·답변 생성 원리

- [ ] **1. 모델은 어떻게 답을 만들까** — 다음 토큰을 확률로 예측·반복 생성하는 원리, 트랜스포머의 어텐션 직관. 같은 질문에 답이 달라지는 데모. 따라하기·퀴즈.
- [ ] **2. Chat Completions API** — `messages`(system·user·assistant)로 대화, `choices[0].message.content`·`usage`. **대화 이어가기(멀티턴)**·**스트리밍(`stream=True`)** 시연 포함. 따라하기(번역기)·퀴즈.
- [ ] **모델 고르기** — 주요 모델 비용·컨텍스트·추론 지원 비교표(공식 문서 링크 포함)와 **실측 비교**(같은 작업을 `gpt-4o-mini`·`gpt-5-nano`·`gpt-5.6-luna` 로 돌린 요금). 단가가 싸도 추론 모델은 '생각 토큰' 때문에 실제 요금이 13배가 될 수 있다.
- [ ] **3. Responses API** — `input`·`output_text`, Chat 과 비교. 따라하기·퀴즈.
- [ ] **4. 파라미터** — `temperature`·`top_p`(무작위성)·`max_tokens`(길이). 온도 0 vs 1.2 비교. 따라하기·퀴즈.
      - **확률분포 개념도** + **직접 계산 실습**: 1절의 그 분포로 `temperature`(0.2/1.0/1.5)가 분포 모양을, `top_p`(0.5/0.9)가 후보 개수를 어떻게 바꾸는지 눈으로 확인 → 그다음 실제 API 에 `top_p` 를 넘겨 본다
- [ ] **5. 사고모드(reasoning_effort)** — 추론 모델·`low/medium/high`·reasoning_tokens(low vs high 비교). 따라하기·퀴즈.
- [ ] **6. 🚀 클론코딩** — 역할(system)+온도를 받는 `ask()` 챗봇 함수를 완성한다.

## 2. 교안_02 — 프롬프트 엔지니어링·도구 호출·구조화된 출력

- [ ] **1. 프롬프트 엔지니어링** — 다섯 원칙을 **하나씩 떼어** 대비 실험: ① 역할 유무 ② 막연 vs 구체 ③ 구분자와 **프롬프트 인젝션 방어** ④ few-shot 0쌍 vs 2쌍(형식 고정) ⑤ 출력형식 지정 + `json.loads` 성공/실패. '나쁜 프롬프트 고치는 순서' 표. 따라하기(**나쁜 프롬프트를 직접 고치기**)·퀴즈 3문(적용형).
- [ ] **2. Function Calling** — 도구 스키마 → tool_call → `json.loads` → 실행 → 재호출(4단계). 리뷰 개수 세는 도구, 도구 없는 질문·라우팅. 따라하기(**새 도구를 직접 정의**해 붙이기 — 인자 없는 스키마)·퀴즈.
      - **4단계 왕복 개념도** — 모델은 '부르라'고 알려 줄 뿐 **직접 실행하지 않는다**(가장 흔한 오해)
- [ ] **3. 구조화된 출력 → 감정분석** — **방법①** JSON 스키마 딕셔너리(`create`+`json.loads`) / **방법②** pydantic `BaseModel`(`parse`+`.parsed`). pydantic 필드 제약(`Literal`·`Field(ge/le)`·중첩 `list[...]`)으로 **측면별 감성 분석(ABSA)** + 측면 집계. 따라하기·퀴즈 4문.

## 3. 교안_03 — 텍스트 데이터 정형화

자유 텍스트를 **집계 가능한 표**로 바꾸는 시간입니다.

- [ ] **1. 왜 정형화인가** — 문장 더미로는 못 센다. 스키마 설계 3원칙(`Literal`·`Optional`·`description`).
- [ ] **2. 고객 문의를 표로** — 유형·긴급도·감정·이슈 키워드·주문번호(없으면 `None`) → DataFrame → 집계. 따라하기·퀴즈.
- [ ] **3. 개인정보 마스킹** — 중첩 스키마(`items: list[PIIItem]`)로 탐지·마스킹, 위험도. **가려졌는지 불변식으로 확인**(탐지한 원본이 가린 문장에 남아 있으면 안 된다). **규칙 vs LLM** 의 경계. 따라하기·퀴즈.
- [ ] **4. 설문 응답 표준화** — 원본 추출 + 표준화 두 층, 품질 등급. **모르는 값은 비운다**(범위 표현은 `None`). 따라하기·퀴즈.
- [ ] **5. 대량 레이블링 파이프라인** — 리뷰 40건 일괄 처리(진행 표시·`try/except` 실패 격리)·별점과 교차 검증·CSV 저장. 따라하기·퀴즈.

## 4. 교안_04 — 이미지 이해와 정형화

- [ ] **1. 이미지를 넣는 두 방법** — **① 로컬 파일(base64 data URL)** / **② 공개 URL**. 언제 무엇을 쓰는지 비교표. 따라하기·퀴즈.
- [ ] **2. 여러 장 비교** — `content` 리스트에 `image_url` 여러 개. 따라하기(패션 두 장 중 어느 쪽이 포멀한가)·퀴즈.
- [ ] **3. 패션 사진 → 상품 속성 표** — 중첩 스키마로 아이템 펼치기(3장 시연), 사람이 붙인 정답표와 대조. 따라하기·퀴즈.
      · ⚠️ 이미지 한 장이 2~3만 토큰이라 **분당 한도(TPM)** 에 걸리기 쉽다 — 429 가 뜨면 1분 뒤 다시 실행
- [ ] **4. 영수증 OCR → 품목·금액 표**(이 절만 상위 모델 `gpt-4o` — 금액을 틀리면 안 되므로) — 중첩 스키마 + **검산(품목 합 == 총액)** + 정답표 대조(총액·상호 각각) + CSV 저장. 따라하기·퀴즈. · 데이터는 인도네시아 루피아 표기이고 **정답표에도 파싱 오류가 있다**(정답표도 의심하라)
- [ ] **5. 참고(채점 없음)** — 웹검색(Responses `web_search`). 눈으로만 익힌다.

## 5. 과제 LV1 (기초) — 한 문제에 개념 하나

데이터: `data/reviews.csv`(자세밴드 40건). 자가채점은 **답의 구조**만 검사합니다.

- [ ] 데이터 살펴보기(제공 셀 실행)
- [ ] **1** 첫 Chat 호출(`answer`) · **2** Responses 호출(`answer_r`)
- [ ] **3** 역할=번역기/변환(`answer_sys`) · **4** 역할=분류기/판별(`answer_label`)
- [ ] **5** temperature=1.2(`answer_t`) · **6** max_tokens=25(`answer_m`)
- [ ] **7** reasoning_effort=**low** 계산(`answer_reason`) · **8** reasoning_effort=**high** 논리(`answer_reason2`)
- [ ] **9** 출력 형식 지시=번호 목록(`answer_list`)
- [ ] **10** 구조화된 출력 ①(딕셔너리 스키마) 감정분석 1건(`result`)
- [ ] **11** 구조화된 출력 ②(pydantic `Sentiment` 직접 작성 + `parse`) — `parsed.sentiment`·`parsed.reason`
- [ ] **12** 파라미터 되짚기 — `top_p` 0.1 vs 1.0 을 3번씩 호출해 **답의 다양성 차이**를 눈으로 확인
      · ⚠️ 표본 3개라 뒤집힐 수 있어 자가채점은 **호출 방식만** 검사한다 — 확률적 현상을 결정적으로 채점하면 정상 답안이 떨어진다
- [ ] **13** 스트리밍(`stream=True` → `chunks`·`stream_text`)
- [ ] **14** 이미지 분석 ① 로컬 파일 base64(`answer_img`) · **15** 이미지 분석 ② 공개 URL(`answer_url`)

## 6. 과제 LV2 (응용) — 개념 조합

데이터: `data/reviews_sun.csv`(선크림 20건). 제공된 `analyze()` 를 씁니다.

- [ ] **1** Function Calling 완성(개수 도구 — `called_name`·`final_answer`)
- [ ] **2** Function Calling(키워드 도구 — `kw_args`)
- [ ] **3** 배치 감정분석+집계(`sample` = 별점별 2건씩 10건 → `results`·`dist`) — CSV 가 별점순 정렬이라 `head()` 로 자르면 분포가 쏠린다
- [ ] **4** 부정 리뷰만 골라 요약(`negatives`·`complaint_summary`) — `sample` 과 `results` 를 순서대로 짝지어야 한다
- [ ] **5** few-shot 별점 분류기(`guess_star`·`star`)
- [ ] **6** 멀티턴 대화(`turn2`)
- [ ] **7** 프롬프트 비교(서술형 — 자가채점 없음, 정답 노트북 모범 서술과 비교)
- [ ] **8** 측면별 감성 **배치** 분석 — pydantic `parse` 반복 + `측면×감정` 집계(`rows`·`aspect_df`)
- [ ] **9** 고객 문의 정형화 배치(`inq_rows`·`inq_df`·`inq_dist`) — 없는 주문번호를 지어내지 않는지 채점한다
- [ ] **10** 개인정보 마스킹(`pii_results`·`found_types`) — 개인정보가 없는 문장은 빈 리스트여야 한다
- [ ] **11** 패션 이미지 정형화(`fashion_rows`·`fashion_df`)
- [ ] **12** 프롬프트 인젝션 방어(`naive_answer`·`safe_answer`) — 구분자만으론 안 막힌다, 역할 고정 + 데이터 뒤 재강조까지

## 7. 과제 LV3 (통합) — 작은 프로그램

- [ ] **프로그램 ① 리뷰 감정분석 리포트**(자세밴드)
  - [ ] 1단계 데이터 로드(`reviews`, 40행)
  - [ ] 2단계 배치 감정분석(`sample` 별점별 3건씩 15건 → `texts_with_hole` → `results`) — 정렬 CSV 를 앞에서 자르지 말 것, 빈 칸 한 건을 끼워 **실패 격리**(`None` 으로 남기고 길이 유지) 훈련
  - [ ] 3단계 집계(`dist`·`neg_summaries`)
  - [ ] 4단계 LLM 리포트 생성(`report`)
  - [ ] 5단계 리포트를 파일로 저장(`output/sentiment_report.txt`, `report_path`)
- [ ] **프로그램 ② 리뷰 상담 어시스턴트**(선크림)
  - [ ] 1단계 데이터·도구 함수 준비(`sun`, 20행)
  - [ ] 2단계 도구 스키마·디스패처(`tools` 3개·`dispatch`)
  - [ ] 3단계 어시스턴트 함수(`ask_assistant`)
  - [ ] 4단계 여러 질문 시험(`answers` 3개) — 앞 둘은 도구가 필요하고 마지막은 도구 없이 답한다(자가채점이 `dispatch` 실행 여부를 확인)
- [ ] **프로그램 ③ 영수증 정산 파이프라인**(영수증 사진)

  - [ ] 3단계 검산: 품목 합 == 총액(`verify_df`·`ok_count`) + **정답표 대조**(`match_count`)

## 막혔을 때

- 준비 셀을 안 돌렸는지 확인 → `client` 가 없으면 모든 셀이 실패합니다.
- `NameError` → 지문이 요구한 **변수 이름**을 정확히 썼는지 확인(예: `answer`, `result`, `dist`).
- 구조화 출력에서 값이 이상하면 → 답을 **`json.loads`** 로 딕셔너리로 바꿨는지 확인.
- Function Calling 재호출에서 400 에러 → assistant 의 `tool_calls` 메시지를 빠뜨렸는지 확인.
- 그래도 막히면 `힌트` 를 펼치고, 최후엔 `정답/` 노트북의 모범답안·해설을 봅니다.

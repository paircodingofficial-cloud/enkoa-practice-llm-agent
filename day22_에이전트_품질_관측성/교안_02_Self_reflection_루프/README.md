# 교안_02 실습: Self-reflection 루프

**이론은 노트북, 4절 실습은 `.py`** 입니다.
`교안_02_Self_reflection_루프.ipynb` 에서 생성 → 비평 → 수정 루프를 조각으로 만들어 보고,
아래 `.py` 로 그 조각을 이어 붙여 **데이터에서 리포트까지** 자동으로 돌려 봅니다.

```bash
uv run 01_자동_리포트.py
```

## 실습 목록

| 파일 | 무엇을 확인하나 | MCP 서버 |
|---|---|---|
| `01_자동_리포트.py` | 요청 한 줄로 분석 → 성찰 → 저장까지, 에이전트 한 대가 | 1개 |

사람이 쓰는 것은 **요청 문장 한 줄**뿐입니다. 나머지는 에이전트가 도구 셋을 골라서 합니다.

| 도구 | 하는 일 | 어디서 온 도구인가 |
|---|---|---|
| `summarize_completion_rate` | 데이터를 읽어 수치 요약 문자열을 돌려준다 | `@tool` 로 만든 파이썬 함수 |
| `write_report` | 요약을 받아 성찰 루프를 돌려 리포트를 돌려준다 | `@tool` 로 만든 파이썬 함수 |
| `files_write_file` | 리포트를 `output/` 에 저장한다 | 파일시스템 MCP 서버 |

읽을 때 볼 곳은 둘입니다.

1. **성찰 루프가 체인으로 조립된 자리**: 노트북에서 함수 세 개로 나눠 만든 생성·비평·수정을
   `프롬프트 | 모델 | 파서` 모양으로 이어 붙였습니다. 새 프로젝트에서는 이 부분을 복사한 뒤 프롬프트만 바꾸면 됩니다.
2. **그 루프를 도구로 감싼 자리**: 순서가 이미 정해진 절차라 모델에게 매번 시키지 않고 묶어 둡니다.
   모델은 그 묶음을 **언제 부를지**만 정합니다.

저장도 파이썬이 아니라 에이전트가 `files_write_file` 을 골라서 합니다.
서버에는 `output/` 폴더만 열어 주므로 그 밖의 파일은 건드릴 수 없습니다.

## 준비물

- **`OPENAI_API_KEY`**: 일차 폴더(`day22_에이전트_품질_관측성`)의 `.env` 에 채웁니다.
- **Node.js(`npx`)**: 파일시스템 MCP 서버를 띄우는 데 씁니다. `npx -v` 로 확인하세요.
  서버는 처음 쓸 때 한 번 내려받으므로 **첫 실행이 느립니다.**

## 산출물

리포트는 일차 폴더의 `output/course_report.md` 로 저장됩니다.
모델이 "저장했습니다" 라고 말해도 파일이 없거나 0 바이트일 수 있으니, 실습 끝의 **크기 출력**으로 확인하세요.

## 과제

`과제/` 폴더에 문제 하나(`.py`)가 있습니다. 실습을 마친 뒤 풀어 보세요.

```bash
uv run 문제1_DB_리포트_에이전트.py
```

실습과 **같은 구조를 다른 데이터로** 다시 만듭니다. CSV 대신 `data/chinook.db`(가상의 음악 판매점)에서
국가별 매출을 뽑아 리포트를 쓰고 `output/country_sales_report.md` 로 저장합니다.
채울 자리는 셋입니다. DB 요약 도구 · 성찰 루프(체인 조립 + 도구로 감싸기) · 에이전트 조립.

## 막혔을 때

- `OPENAI_API_KEY 를 찾지 못했습니다` 가 뜨면 일차 폴더에 `.env` 를 만들었는지 확인하세요.
- `npx` 를 찾을 수 없다고 나오면 Node.js 를 설치하고 **터미널을 새로 연 뒤** 다시 실행하세요.
- 점수 이력이 `[8]` 처럼 한 번에 끝나기도 합니다. 초안이 이미 기준을 넘었다는 뜻이라 정상입니다.
- 저장이 안 되면 기록에서 `files_write_file` 이 불렸는지 먼저 보세요. 도구를 아예 안 골랐다면
  요청 문장에 파일 이름이 들어 있는지 확인합니다.
- 도구가 세 번 다 불렸는지 기록으로 보세요. `write_report` 를 건너뛰고 모델이 리포트를 직접 썼다면
  시스템 프롬프트의 순서 문장이 지워졌는지 확인합니다.

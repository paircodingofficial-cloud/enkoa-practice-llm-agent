# 교안_03: 관측성과 운영 견고성

이 단원은 **노트북 하나로 끝까지** 진행합니다. 에이전트 안에서 무슨 일이 있었는지 알아내는
**관측성**을 Langfuse 로 다루고, 장애를 견디는 **견고성**(예외·재시도·폴백·LiteLLM)을 배웁니다.

`교안_03_관측성과_운영_견고성.ipynb` 를 열어 위에서부터 실행하세요.

## 다루는 것

| 절 | 무엇 | 핵심 |
|---|---|---|
| 1 | 관측성의 개념과 목적 | 로그·지표·트레이스, 모니터링과의 차이, Langfuse 와 LangSmith |
| 2 | Langfuse 구조와 연동 | trace → span → generation, `config={'callbacks': handlers}` |
| 3 | 토큰·비용 읽기 | `response.usage_metadata` 로 집계 |
| 4 | 프롬프트를 코드 밖에서 관리 | 파일로 감 잡기 → `create_prompt`·`get_prompt`·라벨·버전 연결 |
| 5 | 운영 견고성 | `try/except` → 재시도 → 폴백, `ChatLiteLLM` |
| 6 | 실패를 추적하는 워크플로 | 메시지 기록으로 라우팅 확인, 도구 설명을 고쳐 다시 돌리기 |

## 준비물

- **`OPENAI_API_KEY`**: 일차 폴더(`day22_에이전트_품질_관측성`)의 `.env` 에 채웁니다.
- **`LANGFUSE_PUBLIC_KEY`·`LANGFUSE_SECRET_KEY`·`LANGFUSE_BASE_URL`**: 같은 `.env` 에 채웁니다.
  발급 절차는 일차 폴더의 [Langfuse 키 발급 가이드](../Langfuse_키_발급_가이드.md)에 있습니다.

토큰·지연 같은 **관측값은 실제 호출에서만** 나옵니다. 그래서 이 단원은 우회로 없이 실제 API 로 진행합니다.

## 대시보드에서 볼 곳

노트북을 실행하는 동안 [cloud.langfuse.com](https://cloud.langfuse.com) 을 함께 열어 두세요.

- **Tracing → Traces**: 실행 한 건이 trace 로 쌓입니다. 열면 단계별 시간과 토큰이 보입니다.
- **Prompts**: 4절에서 올린 프롬프트가 버전과 라벨을 달고 쌓입니다.

## 과제

`과제/` 폴더에 문제 하나(`.py`)가 있습니다. 노트북을 마친 뒤 풀어 보세요.

```bash
uv run 문제1_라우팅_고치고_관측하기.py
```

6절에서 본 흐름을 **헬스장 회원권** 도메인으로 다시 만듭니다. 이름도 설명도 모호한 도구를 그대로
한 번 돌려 보고, **이름과 docstring 만** 고쳐 다시 돌린 뒤 불린 도구가 어떻게 달라지는지 비교합니다.
채울 자리는 셋입니다. 콜백을 실어 부르는 함수 · 고친 도구 · 다시 돌리고 토큰 집계.

## 막혔을 때

- `OPENAI_API_KEY 를 찾지 못했습니다` 가 뜨면 일차 폴더에 `.env` 를 만들었는지 확인하세요.
- `Langfuse 인증에 실패했습니다` 는 키는 있으나 값이 틀렸다는 뜻입니다. 키를 다시 복사하고,
  가입한 지역의 주소가 `LANGFUSE_BASE_URL` 에 들어 있는지 보세요.
- 셀은 통과했는데 대시보드가 비어 있으면, 전송에 몇 초 걸리니 새로고침하고 화면 왼쪽 위에서
  키를 발급한 프로젝트가 선택돼 있는지 확인하세요.
- 4절에서 프롬프트 업로드가 막히면 그 프로젝트에서의 권한이 Viewer 인지 확인하세요. Member 이상이어야 합니다.
- 5절은 **일부러 실패를 재현**하는 절입니다. 빨간 경고가 지나가도 정상이고, 마지막 출력이 폴백으로 살아났는지만 보세요.

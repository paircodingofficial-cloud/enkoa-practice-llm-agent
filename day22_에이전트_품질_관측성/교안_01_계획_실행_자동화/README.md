# 교안_01 실습: 계획을 세우고 실행하기 (MCP 도구로)

**이론은 노트북, 실행은 `.py`** 입니다.
`교안_01_계획_실행_자동화.ipynb` 에서 미들웨어와 훅을 그림과 함께 읽고,
아래 `.py` 를 하나씩 돌려 그 이론이 실제로 그렇게 도는지 확인합니다.

실행은 **이 폴더에서 파일 이름만** 주면 됩니다.

```bash
uv run 01_프롬프트_비교_그래프저장.py
```

## 실습 목록

| 파일 | 무엇을 확인하나 | MCP 서버 |
|---|---|---|
| `01_프롬프트_비교_그래프저장.py` | 프롬프트 몇 문장 차이로 도구 선택이 갈리는 것 | 3개 |
| `02_계획_세우기_TodoList.py` | `TodoListMiddleware` 로 계획(todos)을 세우고 단계별로 처리 | 3개 |
| `03_자동_분석_파이프라인.py` | 조회 → 계산 → 그래프 → 리포트를 한 번에 | 3개 |
| `04_구조화된_출력.py` | `response_format` 으로 답을 틀에 받아 표·JSON 으로 적재 | 3개 |
| `공통.py` | 서버 설정·경로·허용 도구 (직접 실행하지 않음) | - |

> **프롬프트는 공통.py 에 없습니다.** 각 실습 파일 안에 그대로 적혀 있습니다.
> 파일을 열면 무엇이 모델로 나가는지 그 자리에서 읽히도록 한 것입니다.

네 파일 모두 **실제로 모델을 부릅니다.** 한 번에 수십 초에서 몇 분이 걸리고,
서버를 처음 내려받는 첫 실행은 더 걸립니다. 중간에 실패하면 그냥 다시 실행하면 됩니다.

> 어느 미들웨어가 어느 훅 자리를 쓰는지는 **노트북에서 직접 확인**합니다.
> 모델을 부르지 않는 코드라 노트북 셀에서 바로 돌려 보면 됩니다.

## 준비물

- **`OPENAI_API_KEY`**: 일차 폴더(`day22_에이전트_품질_관측성`)의 `.env` 에 채웁니다.
- **Node.js(`npx`)** 와 **uv(`uvx`)**: MCP 서버를 띄우는 데 씁니다. `npx -v`·`uvx --version` 으로 확인하세요.
  서버는 처음 쓸 때 한 번 내려받으므로 **첫 실행이 느립니다.**

## 산출물

그래프·리포트·JSON 은 모두 일차 폴더의 `output/` 에 모입니다.
코드 실행 서버와 파일 서버를 그 폴더 기준으로 띄웠기 때문에, 모델은 **파일 이름만** 적으면 됩니다.

## 막혔을 때

- `NotImplementedError: StructuredTool does not support sync invocation`: MCP 도구를 `invoke` 로 불렀다는 뜻입니다. 에이전트는 `await 에이전트.ainvoke({...})` 로 부르세요.
- 답이 `Model call limits exceeded` 로 끝나면 호출 상한에 걸린 것입니다. 대개 다시 실행하면 됩니다. 자주 걸리면 `run_limit` 을 올리세요.
- 코드 실행 도구가 **빈 결과**를 돌려주면 `print` 를 빠뜨린 것입니다. 이 서버는 표준 출력만 돌려줍니다.
- `npx`·`uvx` 를 찾을 수 없다고 나오면 Node.js 또는 uv 를 설치하고 **터미널을 새로 연 뒤** 다시 실행하세요.
- `RateLimitError ... tokens per min` 은 분당 토큰 한도입니다. **1분쯤 기다렸다가** 다시 실행하세요.
- `OPENAI_API_KEY 를 찾지 못했습니다` 가 뜨면 일차 폴더에 `.env` 를 만들었는지 확인하세요.

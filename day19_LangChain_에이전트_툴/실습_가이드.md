## 1. 교안_01 — 구조화된 출력·도구·MCP

- [ ] **1. 구조화된 출력** — 지난 단원에서 손으로 하던 **정형화를 LangChain 부품 한 줄**로. 스키마 규칙(`Literal`·`Optional`·`description`)은 **복습으로 짚고** 넘어가고, 새로 외울 것은 `model.with_structured_output(스키마).invoke(문장)` 하나다. 결과가 **문자열이 아니라 객체**로 오는 것, 분류기를 **한 번 만들어 여러 문의에 재사용**하는 것, 구조화된 출력을 배운 단원의 `parse` 와의 대응(**모델 회사를 바꿔도 스키마·호출은 그대로**). 따라하기(회의실 예약 문의)·퀴즈.
- [ ] **2. 도구 만들기(`@tool`)** — docstring 이 명세, 타입힌트가 인자 타입. `.name`·`.description`·`.args`, 모델에게 넘어가는 **JSON 명세**(`tool_call_schema.model_json_schema()`), 도구를 직접 불러 보기(아직 모델은 등장하지 않는다). **⚖️ 구조화된 출력 vs 도구** 갈림길("이 답을 만들려면 우리 데이터를 뒤져야 하나?"). 따라하기(구내식당 메뉴 도구)·퀴즈.
- [ ] **3. `create_agent` 와 메시지 궤적** — `agent.invoke({'messages': '질문'})`, 사람→AI(도구호출)→ToolMessage→AI(최종답). `system_prompt` 로 역할 부여, 도구가 필요 없는 질문(호출 0회), `response_format` 으로 **도구도 쓰고 답도 스키마로**. 따라하기(회의실 좌석 도구)·퀴즈.
- [ ] **4. 의미 있는 도구 만들기** — **실패는 문자열로 돌려준다**(예외를 던지면 에이전트가 그 자리에서 멈춘다), **할 수 있는 일을 좁게**(읽기 전용·상한을 도구 안에). 실무형 도구 3종(사내 데이터 조회·규칙 계산·**외부 REST API** — `try`/`except` 로 실패도 문자열로). 따라하기(주차 등록 도구)·퀴즈.
  - *도구가 여럿일 때 생기는 문제(설명이 선택을 좌우한다·인자를 다듬는다)는 **다음 단원**에서 증상과 함께 다룹니다.*
- [ ] **5. MCP** — 표준 규격이 필요한 이유, USB-C 비유, 클라이언트/서버. `MultiServerMCPClient`(stdio)로 **이미 있는 서버에 붙어** `get_tools()` → `create_agent` → `asyncio.run(agent.ainvoke(...))`. **우리 도구와 MCP 도구를 섞어** 붙이기. (서버를 직접 만드는 것은 이 단원 범위가 아닙니다.) 따라하기(서버의 다른 도구)·퀴즈.

## 2. 교안_02 — RAG 파이프라인·검색 평가·Text-to-SQL

- [ ] **1. RAG 를 LangChain 부품으로** — 앞선 RAG 단원에서 손으로 만든 것을 부품으로 다시. `Document`(page_content·metadata) → `RecursiveCharacterTextSplitter`(metadata 가 조각에 따라붙는다) → `HuggingFaceEmbeddings`(768차원) → `Chroma.from_documents`(**`ids` 를 넘겨 여러 번 실행해도 중복되지 않게**) → `as_retriever(search_kwargs={'k': 2})`. 따라하기(서점 FAQ)·퀴즈.
- [ ] **2. RAG 체인(LCEL)** — `{'context': retriever | format_docs, 'question': RunnablePassthrough()} | prompt | model | parser`. "자료에 있는 내용만으로 답하라"가 왜 필요한가. `RunnableParallel` 로 **근거를 함께** 돌려받기(출처 없는 RAG 답은 실무에서 못 쓴다). 따라하기(서점 안내 체인)·퀴즈.
  - 절 끝에 **미결 하나**를 남깁니다 — 인사말을 넣어도 검색이 도는 것을 눈으로 보고, **다음 단원**에서 해결합니다.
- [ ] **3. 만들었으면 잰다 — 검색 평가** — 평가셋 3요소(질문·정답 라벨·근거), **문항 수가 곧 눈금**(20문항이면 한 문항이 0.05). ⚠️ 라벨은 문서가 아니라 **조각**에(문서 단위는 답 없는 조각에도 점수를 준다 = 허위 크레딧). 평가 전용 색인은 **제공 셀**로 세웁니다. Hit@K·Precision@K·Recall@K·MRR 을 손으로 구현하고 손계산과 대조 → **질문별 표를 먼저, 평균은 나중에.** 읽는 법 2가지: 1) 평균은 실패를 뭉갠다(Hit=0 인 문항을 꺼내 읽기) 2) Recall 은 **정답 개수와 함께** 읽는다(정답 7개인데 K=3 이면 최대 0.43). **K 두 값을 나란히** 재서 맞바꿈 확인. 따라하기(질문 출처별로 나눠 보기)·퀴즈.
- [ ] **4. Text-to-SQL** — 표 구조를 프롬프트로 알려 주면 모델이 SQL 을 만든다(**모델은 DB 를 못 본다 — 스키마 설명이 모델의 눈**). 데이터 살펴보기 → **두 겹 가드**: 1) `run_select` 의 문자열 검사(SELECT 한 문장만) 2) **읽기 전용 연결**. `union` 을 섞은 조회처럼 **문자열 검사를 통과하는 SELECT** 를 직접 실행해 "문자열 검사만으론 못 막는다"를 확인하고, 읽기 전용 연결에 쓰기를 시도해 막히는 것도 확인. 궤적에서 **모델이 만든 SQL** 을 꺼내 보기. **구조화된 출력으로 SQL+근거+사용한 표** 받기. 따라하기(서점 DB)·퀴즈.

## 3. 과제 LV1 (기초) — 도구 정의·궤적·검색 평가 (12문)

데이터/도구: 준비 셀에서 제공. 도구를 **만드는** 문제는 직접 호출로(결정적), **에이전트 궤적** 문제는 실호출이라 도구가 최소 1회 불렸는지로 채점. **9~12번은 모델도 데이터도 쓰지 않는 순수 계산**이라 값을 정확히 채점.

- [ ] **1** 할인가 계산 도구(`discount_price`) · **2** 제목 정리 도구(`clean_title`)
- [ ] **3** 도구 명세 읽기(`tool_name`·`tool_desc`·`arg_names`)
- [ ] **4** 배송비 도구 궤적(`res4`·`tool_msgs4`)
- [ ] **5** 도구가 필요 없는 질문(`res5`·`n_tools5`=0)
- [ ] **6** 역할 부여(정중, `res6`·`tool_msgs6`)
- [ ] **7** 구조화 출력 — `with_structured_output` 부품 재사용(`reviewer` 하나로 리뷰 두 건 → `summary_a`·`summary_b`; 스키마는 제공, 채점은 타입·방향)
- [ ] **8** 메시지 타입 개수·서술(`n_human`·`n_tool`·`n_ai`)
- [ ] **9** Hit@K(`hit_at_k(ranked, gold, k)` — 상위 k개 안에 정답이 있으면 1.0) · **10** Precision@K(`precision_at_k` — 나누는 수는 언제나 k)
- [ ] **11** Recall@K(`recall_at_k` — 전체 정답 개수로 나눔) · **12** MRR@K(`mrr_at_k` — 첫 정답의 순위 역수, 없으면 0.0)

## 4. 과제 LV2 (응용) — RAG 체인·검색 평가·SQL·MCP·외부 API (7문)

- [ ] 준비 셀 실행(FAQ 검색기·에이전트 공통·평가 코퍼스)
- [ ] **1** RAG 체인 직접 조립(`rag_chain`·`answer1`·`chain_with_sources`·`result1` — `{context, question}` → 프롬프트 → 모델 → `StrOutputParser`, `RunnableParallel` 로 근거 함께)
- [ ] **2** 검색 품질 재기(`eval_results`·`eval_summary`·`missed2` — 평가셋 25문항을 K=3 으로, Hit 약 0.96·P 약 0.53·R 약 0.73·MRR 약 0.92)
- [ ] **3** K 를 바꿔 가며 비교(`k_table` — K=1·3·5·10, Recall 은 오르고 Precision 은 떨어지는 맞바꿈) + **서술 답안**(K 를 얼마로 정할지·근거)
- [ ] **4** Text-to-SQL 주문 건수(`res4`·`tool_msgs4`, 도구 결과 어딘가에 c1=3) + **답까지 스키마로**(`response_format=ProviderStrategy(OrderAnswer, strict=True)` → `res4b`·`report4`) — SQL 준비 셀 실행(sqlite, 준비물 없음)
- [ ] **5** MCP 도구 연결(`res5`·`tool_msgs5`, 9100원→7.0달러) — 비동기·MCP 준비 셀 실행
- [ ] **6** MCP 구조화 수집(`df6` — '소설' 신간→`title·author·price·summary` 표)
- [ ] **7** 외부 API 도구 직접 만들기(`jpy_krw_rate`·`used7` — 오늘 환율로 엔화 환산, 채점 셀이 같은 API 로 대조)

## 5. 과제 LV3 (통합) — 리뷰 인텔리전스·검색기 평가 (2문)

- [ ] 준비 셀 실행(모델 공통)
- [ ] **1. 리뷰 인텔리전스 파이프라인** — 1단계 측면 감성 구조화 수집(`batch`·`records`) → 2단계 pandas 집계(`neg_by_aspect`) → 3단계 측면별 교차집계(`summary`)
